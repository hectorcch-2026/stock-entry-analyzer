### 2.2 方法一：ZQ 期貨反推（復現 CME FedWatch 演算法）

隱含月均利率 = 100 − ZQ 期貨結算價

來源：Yahoo Finance 期貨報價（CBOT 交易所），經專案 `datasource` 層取得。

**加權方式（會議前後拆天）**

2026-12 共 31 天，FOMC 於 12/09 決議、12/10 起生效，故：
- 會議前 **9 天** 按舊利率 3.880%
- 會議後 **22 天** 按新利率 X

設月均 = 4.055%，解：

```
(9 × 3.880% + 22 × X) / 31 = 4.055%
→ X = 4.1266%
→ 回代校驗：(9×3.880 + 22×4.1266)/31 = 4.0550% ✓
```

**相對當前有效利率 3.880%，隱含升息 24.7bp。**

| **升 1 碼（25bp）** | **98.6%** |
| 升 2 碼（50bp） | 0.0% |

### 2.5 是否已有更新資訊？

**是的，且已納入本報告。** 需特別說明一處資料陷阱，這是「升息 2 碼」說法最可能的來源：

Yahoo 的 `ZQ=F`（連續合約）最新報價為 **95.85（隱含 4.15%）**。若直接採用，會誤得「隱含升息 27bp、接近 2 碼」的結論。

**但 `ZQ=F` 根本不是「當前月份」合約。** 實測比對發現，`ZQ=F` 與 **`ZQF27.CBT`（2027 年 1 月）** 的報價、最高、最低、成交量、甚至時間戳**完全逐位元相同**：

| 欄位 | `ZQ=F` | `ZQF27.CBT` | 是否相同 |
|---|---|---|---|
| 最新價 | 95.85 | 95.85 | ✅ |
| 當日高 | 95.855 | 95.855 | ✅ |
| 當日低 | 95.85 | 95.85 | ✅ |
| 成交量 | 738 | 738 | ✅ |
| 時間戳 | 2026-11-26 01:20:09 UTC | 2026-11-26 01:20:09 UTC | ✅ |

連續合約早已**滾動到 2027 年 1 月**（`ZQ=F` 的成交量級別 127,043–738 也與 `ZQF27.CBT` 一致，而非 12 月合約的 54,523）。換言之，用 `ZQ=F` 反推 12/9 會議，等於**拿兩個月後的合約去定價下一次會議**——月份錯配，必然得出偏高的利率。

> **訂正**：本報告初稿曾把 738 手解讀為「亞洲時段稀薄報價」。實測顯示 738 是**當日交易尚未結束**的即時量（12 月合約同時點亦僅 232 手，而其前一日全日量為 54,523 手），流動性本身正常。真正的錯誤來源是**合約月份選錯**，不是流動性不足。

**本報告改用決議當月合約 `ZQZ26.CBT`**（95.9450），並以 11 月合約 `ZQX26.CBT`（96.1200）與 EFFR 3.88% 驗證，結論才可靠。這是 FedWatch 復現最關鍵的實作細節：**必須用「決議所在月份」的合約，不能用連續合約**（連續合約的月份由持倉量決定，與會議日期無關）。

### 3.2 更新頻率與時效原則

| 資料類型 | 天然更新頻率 | 本報告採用原則 |
|---|---|---|
| 日頻利率、期貨、股價 | 每交易日 | **取最新一筆，並標註成交時點與成交量** |
| 月頻總經 | 每月一次 | 標註「資料月份」而非抓取時間 |
| 個股財報 | 每季（10-Q）／每年（10-K） | **標註財報期別**，並檢查是否超過 1.5 年 |

2. **財報期別的可用性檢查**：實測發現 GOOGL 若用錯概念會取到 **2024-12-31**（落後 1.9 年）。本報告已改為「取最新 end 日期」邏輯並驗證，確保期別在 1 年內（AAPL 0.17 年、MSFT 0.41 年、XOM 0.16 年）。

#### 4.2.2 第二層：DBnomics 有 ISM provider，但有兩個致命問題

**DBnomics 的 `ISM` provider 確實存在**，含 **24 個資料集**，涵蓋製造業 12 項與非製造業 12 項，頻率均為**月頻**。這是原本 FRED 拿不到的真實 ISM 資料。但實測發現：

| 2025-11 | **10.0** | ❌ 不可能 |
| 2025-12 | **10.3** | ❌ 不可能 |

## 附錄 B：連續合約 vs 月份合約的關鍵差異

FedWatch 復現最容易出錯的地方：

| 合約 | 代碼 | 報價 | 隱含利率 | 隱含升息幅度 | 判定 |
|---|---|---|---|---|---|
| 連續合約（已滾至 2027-01） | `ZQ=F` | 95.85 | 4.150% | +27bp（≈2 碼） | ❌ **月份錯配** |
| 11 月合約 | `ZQX26.CBT` | 96.1200 | 3.880% | 基準（=EFFR 3.88%） | ✅ 校準用 |
| **12 月合約（決議當月）** | **`ZQZ26.CBT`** | **95.9450** | **4.055%** | **+24.7bp（≈1 碼）** | ✅ **用於反推 12/9** |

若誤用 `ZQ=F`，會得出「升息 27bp、接近 2 碼」的錯誤結論——**這正是「升息 2 碼」說法最可能的來源**。兩者只差 3 個基點的表面數字，卻跨了一個完整的會議，導致機率分布完全走樣（98.6% 對 0%）。正確做法是：**用決議所在月份的合約，並以 EFFR 或國庫券利率交叉驗證**。

### C.4 API 查詢路徑

基礎路徑：`https://api.db.nomics.world/v22`

| 用途 | 路徑 | 說明 |

### C.7 建議的接入做法（若仍要使用）

若未來 DBnomics 修復了此 provider，接入時**必須**加三道防線：

```js
// 1. 值域檢查：PMI 低於 30 視為可疑（實務極少發生）
if (v < 30) throw new Error(`PMI 值異常: ${v} @ ${period}`);

// 2. 跳動檢查：單月變動超過 20 點視為可疑
if (Math.abs(v - prev) > 20) throw new Error(`PMI 跳動異常: ${prev} → ${v}`);

// 3. 新鮮度檢查：indexed_at 超過 90 天即視為過期
const ageDays = (Date.now() - new Date(dataset.indexed_at)) / 86400000;
if (ageDays > 90) throw new Error(`資料過期 ${ageDays.toFixed(0)} 天`);
```
